# R6. A second budget provider (OpenAI or Gemini)

Status: done (v0.8.0)
Date: 2026-10-26
Roadmap: [2026-10-26-roadmap.md](2026-10-26-roadmap.md)

## Problem

Agents are agent-agnostic now, providers are not: only `anthropic` (plus `spend` and `mock`).
A Codex or Gemini user on their own plan cannot watch their own window.

## Requirements

R6.1. Pick the provider whose usage/limit data is reachable with what the user already has
      (CLI login or API key), documented endpoint preferred; record the choice and why here
      before code.
R6.2. `providers/<name>.sh` (+ `.ps1`) prints the standard lines `<window> <util%> <reset_epoch>`,
      fails with a human message on stderr and non-zero exit, never prints a fake zero.
R6.3. Token lookup order documented; the token goes only to the provider's host; "What it
      touches" lists the endpoint and credentials.
R6.4. Tests with recorded responses (no network), both suites.

## Out of scope

Billing/spend for that provider beyond what R6.2 needs.

## Decision (R6.1, 2026-10-27)

**OpenRouter** (`providers/openrouter.sh|ps1`). Neither Codex nor Gemini CLI is on this
machine, and neither exposes a documented per-user usage window; OpenRouter does
(`GET https://openrouter.ai/api/v1/key`, Bearer key: `limit`, `limit_remaining`, `usage`,
`limit_reset`), it is what opencode here is configured with, and it serves any agent that
routes through it. The key comes only from `$OPENROUTER_API_KEY`: no reading of another
tool's credential files.
- Key with a limit: window = `day` / `week` / `month` from `limit_reset` (or `key` if none),
  utilization = spent / limit, reset = next UTC midnight / Monday / 1st (or `-`).
- Key without a limit: `CONTINUUM_OPENROUTER_CAP` (dollars) as the budget against `usage`,
  window `key`, no reset; without a cap the provider fails with a message (never a fake 0).
- `OPENROUTER_API_BASE` (https:// or file://) for tests with recorded responses.

Follow `docs/writing-a-provider.md`; `mock.sh` is the template.
